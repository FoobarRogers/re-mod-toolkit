# Evidence 格式化 workflow：把存量证据转为可引用结构

## 目的

存量 evidence 通常是时间线追加式的自由文本（调查记录、crash 记录、review 萃取）。kb 知识库（`re-mod-kb`）按 heading 切块检索、靠节头状态行与文件级认识状态声明传递证据等级——未格式化的文件检索时缺口径、分不清"定案"与"进行中"。本 skill 把存量 evidence 转为可引用结构，**不重写正文、不丢证据**。

## 核心原则（执行前先读，防走偏）

1. **轻量增强优先，不重写正文**：正文是证据（append 语义），转换只加结构（声明、状态行、原版问题），不重排不删改已有内容。大文件（>20KB）与时间线型文件只做轻量增强，重写仅限小而清晰的定案型。
2. **零丢失**：转换前后节数、代码围栏、行号引用（`xxx.lua:NNN` 形态）、"效果"行数量不得减少。验收前先备份原文。
3. **状态行是拦截器，不是仪式**：只有实测佐证或硬性条件限制的节才加节头状态行；全部节头铺满相同状态行会稀释真正要拦截的信号。默认状态由文件级声明承载。
4. **区分观察与结论**：测量值照抄，评价性措辞（"接近下限""成本可忽略"）必须标注来源性质（审查判断/推断）；整入口实测值不可归因到单个模式。
5. **跨文件时间线联动**：同主题的文件序列（发布系列 bake2.1→2.2→2.3、test 序列、旧版/新版分析）格式化时，必须检查**后续文件是否修正了本文件的定案**——release 产出轮的论证推翻前期研究时，前期文件的状态行不得保持裸的正面状态（含实测佐证/已定案），应改为"部分有效/已推翻"+ 现行定案指针（跨文件指针写文件名），文件头声明补"时序位置"段。判定依据：在系列后发文件里 grep 修正信号（"实测发现…仍/未/只"，"扩为/取代/作废"，基线行）。对象版本不同（分析 2.x 版 vs 分析 3.0 版）不算推翻，不联动。
5. **kb 解析契约**（格式必须是 server 能解析的）：节头状态行 `> [状态：…]`（紧跟节标题行，正则 `^\s*>\s*\[状态[：:]`）；文件级声明 `- 认识状态：`/`- 认识状态说明：` 开头的行（位于文件头部元信息区）；heading 按节号 `^### N. ` 精确检索。

## 第一步：清点与判型

`ls docs/evidence/` 逐份判型（看文件头与章节结构即可，不整读大文件）：

| 类型 | 特征 | 转换深度 |
| --- | --- | --- |
| **模式/定案型** | 每节是独立结论（模式萃取、verdict 裁决、机制定案），有"问题→方案"结构 | 全量转换：原版问题 + 模式做法两分区 + 节头状态行按例外制 |
| **时间线型** | 长调查记录按日期追加（investigation 大文件），多轮实测混合定案与过程 | 轻量增强：文件头声明 + 已定案节头补状态行 + 被推翻旧节加指针；正文不动 |
| **交付/发布记录型** | 单版本定稿记录（发布说明、交付总结），含定案但各节是散文（变更/验证/限制/交付形态），无"实现方式/效果"类字段 | 轻量增强：文件头声明（按 §1 替代文本）+ 有实测/实机佐证的节加状态行；正文不动 |
| **待定型** | 调查进行中，无定案节 | 仅文件头声明（认识状态=进行中）；节头不动 |
| **原始证据目录** | crash 目录、日志、dump、capture JSON | 不转换。确保 kb_list 的清单层登记它们（server 自动处理），检索走 data-researcher |

判型兜底：体积小**不**等于能全量转换——全量转换的前提是节结构本身匹配两分区模板（有可迁移的"实现方式/效果"类内容）；结构不合模板时无论多小都走轻量增强，避免为套模板而重排正文。

## 第二步：按型执行转换

完整模板、状态行三槽位定义、认识状态声明标准文本、效果标注体系（【实测】/【裁决】/【源码】/【推断】）、真实样板（公区 arena-music-override 最小样本 / better-matchmaking 最大样本含 4 个例外状态行节）——**读 `references/evidence-format-spec.md` 再动手**。

动作速查：

- **文件头**：元信息区（h1 之后、第一个 `##` 之前）加 `- 认识状态：…` 行（标准文本见 spec）。文件内标注体系有特殊口径（如全部【推断】）时，追加 `- 认识状态说明：…` 覆盖行——server 取最后两行，覆盖行放后。
- **模式/定案节**：`- **原版问题**：`（之前为什么不行，只能从原文"目的"或 review 显式化，禁止编造）+ 原"实现方式"改称"**模式做法**"（代码与行号逐字保留）+ 效果/复用提示原样。
- **节头状态行**（例外制）：实测佐证 → `> [状态：含实测佐证] <引证据>`；硬条件 → `> [状态：条件受限]` + `> [代价/条件]` 两行；被推翻结论 → `> [状态：已推翻] <现行定案指针>`。紧跟节标题行。
- **时间线型定案节**：只加节头状态行（如 `> [状态：实测通过] 日志 10414-10435 定案`），过程节不动。
- **推翻指针**：新定案推翻旧结论时，旧节头部加状态行（可行性 + 代价 + 现行定案指针），原证据保留。

## 第三步：验收（零丢失 + 可解析）

逐份核对（脚本或人工）：

1. 节数 = 转换前（有编号节按 `^### ` 计数；全 `##` 无编号文件按 `^## ` 计数，避免 0=0 恒真失效）；代码围栏（``` 计数）≥ 转换前；行号引用数 ≥ 转换前；"效果"行数 = 转换前。
2. 模式/定案节的 `- **原版问题**：` 行数 = 该类节数；内容抽读 2-3 条核对无编造。文件无该类节时本判据记"不适用"，不算通过也不算失败。
3. 状态行总数 ≤ 总节数 40%（抽查口径，实体规则优先：真有实测佐证就加）。"已知限制/限制清单"类节不加状态行——内容与正文重复即为仪式化。
4. kb 解析验证：调 `kb_search`（选文件内已知词）确认命中、`kb_read` 确认文件级口径与状态行随返回。执行实体无 kb 工具时，降级为 spec §8 的静态正则自检（状态行格式、声明行序），并在回报中标注"待主会话实机补验"——主会话收到回报后必须补验，不得把静态自检当作实机通过。
5. 备份保留至用户确认后再清理。

## 批量模式（≥5 份时）

1. 备份全部原文到 `%TEMP%` 或项目 archive 外的临时目录。
2. 先做 1 份最小样本 + 1 份最大样本给用户过目，格式确认后再批量。
3. 批量派发 deepseek-worker：任务包含——格式权威（样板文件绝对路径）、逐节改写规则、范围与保护清单（不得动样板/索引/备份）、自验五项、回报格式（每份节数/状态行节号/不确定点待裁决）。参考本 skill 作者会话的实际任务包（r4 批量 17 份，91 节零丢失）。
4. worker 回报后主会话做**独立复核**（不用 worker 的脚本：自己跑计数对比），再处理 worker 列出的待裁决点。
5. 索引文件（若有）同步：相对链接按部署布局校正、规模口径标"历史采集 vs 当前库存"。

## 已知陷阱（实战踩过）

- 节头状态行漏 `[状态：]` 头行（只有代价行）→ server 不解析，形同虚设。
- heading 节号检索是精确语义：`2.` 不匹配 `12.`/`2.1`——写节号引用时不用担心歧义，但转换时不要把节号写成非标准形态。
- 效果行引用别处的整体实测（如"on_frame 0.105 ms/帧"）不等于本节模式被实测——状态行要写归因边界。
- 文件内标注体系与统一声明冲突时（如全文件【推断】），必须加覆盖行，否则 kb 返回的默认口径误导。
- 相对链接在文件移动后会断（索引在根、模式在子目录时要补 `evidence/` 前缀）。
