# Armor Variant Manager（AVM）JSON 规范

## 定位

AVM 是“外观部件和预设配置层”，通常负责：

- 默认部件显隐
- 差分分组
- 零件预设
- 组合预设
- 装备 ID / body ID 对应
- 剧情/特殊场景使用的预设（若项目实现）
- 从其他配置复制/适配（若所用版本支持）

具体字段以项目当前 AVM 版本和已验证 JSON 为准。

## 修改原则

1. **先找同类的已验证 JSON 当 schema。**
2. 不删除/重排不理解的字段。
3. 不凭字段名猜语义后批量改。
4. 只改目标装备/部位对应项。
5. 修改文件名时同时检查内部 ID。
6. 当前装备 ID 与原始 mod 的 body ID 不一致时，明确记录映射关系。

## 新装备 ID 适配

典型流程：

```text
确认当前装备 ID
→ 找到原 mod 已验证 AVM JSON
→ 核对 body ID / 部位结构
→ 复制为当前装备 ID 对应版本
→ 只改必要映射
→ 校验 JSON
→ 实机验证默认/差分/组合
```

不要只改文件名就默认一定成功；是否需要同步内部字段必须以当前 AVM schema 为准。

## 组合预设

验证至少覆盖：

- 默认分组
- 一个差分分组
- 组合预设加入后
- 切换装备/重载脚本后
- 剧情/CG（若项目支持）

## 与 LuaBone 的边界

AVM 决定“哪个部件显示/使用哪组预设”；
LuaBone 决定“运行时骨骼怎么适配”。

如果：
- 部件根本没出现 → 先查 AVM / 模型加载
- 部件出现但姿态错 → 再查 LuaBone / mesh
- 部件出现且姿态正常但材质错 → 查 texture/MDF

## JSON 工具纪律

- 先 parse 校验。
- 输出 diff，而不是完整 JSON。
- 大量配置批处理时写离线脚本。
- 批处理脚本先 dry-run，打印将修改的文件名和字段，不直接覆盖。
- 覆盖前保存备份或依赖 git 分支可回退。
