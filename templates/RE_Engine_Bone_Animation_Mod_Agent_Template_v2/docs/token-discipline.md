# Token / 上下文纪律

本文件只规定**大数据和工具输出的处理方式**。何时停止调查、何时落盘、何时进入 Review，由全局注入的 DeepSeek Discipline 与 `review-protocol.md` 决定。

## 1. 原始大数据不进入主上下文

对大型日志、JSON/CSV、dump、反汇编、资源清单、逐帧数据、大型 diff 或其它高体积证据：

1. 在本地脚本或专用数据工具中解析；
2. 先按当前 discriminator 过滤；
3. 原始结果写入项目指定的 `evidence/`、`tmp/` 或工作区文件；
4. stdout 只返回会改变下一步决策的摘要和稳定证据指针；
5. 后续优先二次筛选结果文件，不重复扫描原始大文件。

## 2. 默认 stdout 协议

一次只读调查默认返回：

- 扫描对象与条件；
- 命中数量；
- 最相关的少量命中；
- 关键差异 / 数值 / 失败项；
- 简短结论与证据文件位置。

除非任务明确需要，不打印完整 table、完整 JSON/DataFrame、全量 grep、全量文件树、逐帧/逐对象全表或数百行 diff。

## 3. 批量观测

同一 discriminator 已知需要多个只读观测时，优先一次脚本或一次批量工具调用完成，并输出紧凑摘要。

不要为了减少工具调用而把互不相关的假设、修改或验证目标混在同一实验中。

## 4. 图片与二进制证据

截图、录屏、二进制解析和反汇编完成后，将判定、关键证据点和源文件位置落盘。后续只有新问题需要像素级或指令级复核时才重新读取原始材料。

## 5. 会话边界

对话承担当前工作，不承担长期知识库存。阶段完成后把可复用事实写入项目事实索引 / workflow / adaptation / handoff。

当新的工作阶段已经能从持久文档独立恢复时，优先新开任务，而不是让一个 Session 长期承载多个已闭环阶段。
