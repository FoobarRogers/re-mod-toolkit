# 动画管线规范

> 本文件是骨架。项目建立自己的实测管线后，把具体脚本、参数和门禁写进来，并注明口径来源。

## MOT / MOTLIST 最小结构

- motlist = 槽表（名字 / 帧数 / 头部字段）+ 逐槽 mot blob；运行时动作 id 与文件槽序**不是同一回事**，以实机探针读数为准。
- mot blob 内：骨骼表（条目含父条目指针）、track 表（每骨一条，flags 展开为 T/R/S 曲线链）、曲线头（键数 / 时间戳区 / 值区）。
- 量化布局槽与 float 布局槽的解析方式不同：混用解析器会产生"体转 180°"之类的假象。
- 项目首次解析成功后，把二进制布局要点和解析函数出处补进本节。

## 修改方式三档

| 方式 | 适用前提 | 风险 |
| --- | --- | --- |
| 整条 blob 复制 | 两槽同骨架、动作同族，速度观感可接受 | 源数据固有姿态一并带入 |
| 就地换个别曲线（换血） | 两槽曲线头一致（键数 / fmt / unpack / 时间戳逐字节相同） | 前提不满足时静默错位——必须先跑前提检查 |
| 重建 blob | 键数 / 布局不同，或需要重采样 / 收敛 | 工程量最大；同一根骨所有曲线同一策略 |
| 基础姿态偏置（bias） | 把一条循环的静止风格对齐另一条（如肩宽统一）；只改目标关节的 R 曲线 | q_bias = 目标均值 ⊗ 源均值⁻¹ 逐键左乘（= 父空间固定旋转）；左右乘序离线定不了，需一次实机确认；键数 / 时间轴 / twist / 邻近补偿骨不碰，循环闭合自动保持 |

判定循环还是过渡：闭合性（首末帧 RMS）、俯仰走势（漂移 vs 周期）、末帧去向、逐帧距离形状。
四判据与工具形态见 `animation-bake-tuning` skill。

## 烘焙流程骨架

1. 记录基线：离线验收器对当前 Field 全过。
2. 只改一处；改后自验"其余槽逐字节不变"。
3. 离线验收（结构 + 逐字节 + 语义级分区确认）全过才打包。
4. 打包 → 用户手工部署 → 实机验收 → 回填 handoff。

## 验收门禁

- 离线验收器全过；`--extra-rewritten` 类参数如实登记额外重写槽。
- 逐字节断言：除目标区外与基准一致。
- 语义级确认：改动区域对照各自来源应趋近 0°，非目标区域保持不变。
- 实机判据先行声明（探针读到什么 = 生效铁证）。

## 实机判据纪律

先实机读数再离线推理：动作身份（探针读动作名 / id）未确认前，不要基于间接特征改动数据。


## 运行时症状诊断路由

画面异常先确认**实际动作身份**（id / 名称 / layer / 切换频率），再解释动画数据；身份未确认前，不依据“看起来带位移”“末帧像待机”等间接特征改 MOT。

- **不播放 / 播错槽**：运行时 id ↔ 文件槽序映射、覆盖包互斥、加载顺序；
- **已播放但姿态错**：曲线值、骨架 hash 集合、换血前提、重建策略是否混用；
- **脚滑 / 脚漂 / 浮空**：位移承载层、IK 目标世界语义、步频与位移速度；
- **抖动 / 第一帧跳**：静态 / 动态曲线混用、首帧衔接角；
- **过渡断裂 / 末帧跳**：收敛目标、末帧衔接、循环闭合性；
- **朝向错误 / 自转**：根运动结算、朝向基底、覆盖包冲突。

### 部署与缓存

项目应记录真实生效方式（重新应用包、重启游戏、重新读档等）。一次“没变化”不能单独证明修改无效；先排除 Manager 部署和缓存。

覆盖同一 motlist 的包必须互斥。冲突验证从 baseline + 当前包开始，再逐个恢复其它同路径覆盖包。

通用最小实验、Failure Brake、证据落盘与 Review 由全局注入的 DeepSeek Discipline / `review-protocol.md` 管理，不在此重复。
