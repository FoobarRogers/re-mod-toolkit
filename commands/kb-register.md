用户调用本命令，授权把项目工作区登记进 kb 知识库注册表。登记制语义：
**只有登记过的项目才进入检索池**；约定根扫描只用于发现未登记项目（由
`/kb-doctor` 提醒），不会自动混入检索。本命令是唯一写操作：只写注册表，
永不写任何项目 docs 文件。

用户参数：$ARGUMENTS

**路径契约（与 MCP server 一致）**：注册表保存**工作区根目录**，server
统一解析为其下 `docs`。不要登记 docs 路径本身。

**先确认注册表位置**：server 读取 `KB_REGISTRY` 环境变量指定的注册表文件
（在 ZCode 配置的 `re-mod-kb` server env 中查看），未设置时为
`~/.zcode/kb/registry.json`。两个路径不一致时以 env 为准并告知用户。

## 常规登记 `<工作区根> [别名]`

1. **解析与检查**：路径其下必须存在 `docs` 目录；列出该 `docs` 一级结构
   确认分位形态（evidence/history/review/archive）。没有 docs 时停止说明。
2. **幂等检查**（读注册表后按序判断）：
   - 同一别名且路径相同 → 回报"已登记，无需改动"，结束；
   - 同一路径已有其它别名 → 回报现有别名即可，**不提供"再加别名"**
     （同一路径仅保留一个正式别名，server 侧也会去重）；
   - 同一别名但路径不同 → **报告冲突，不覆盖**，等用户裁决；
   - 新条目 → 增量写入 `libraries`，不触碰其它条目。
3. **写注册表**：`{ "libraries": { "<别名>": { "path": "<工作区根>",
   "comment": "<来源与日期>" } } }`；文件或目录不存在则先创建。
4. **验证闭环**：先调 `kb_list(project="<别名>", depth=0)` 确认库名出现、
   来源显示 registry。current 范围有文档时再做检索抽验：用默认 depth 重新
   `kb_list` 取标题树，选一个**已知存在的节标题词**（无标题文档则 `kb_read`
   读文件开头，从正文选独特词）调 `kb_search` 确认命中，必要时 `kb_read`
   取回原文。current 为空时跳过检索抽验——登记仍算成功；docs 无任何 md
   时回报"已登记，暂无可索引文档"。不要凭空想领域词判断失效。
5. **回报**：别名、路径、来源、文件数、验证输出摘要。

## 批量登记 `--scan`

用于首次配置：扫描约定根（server 默认 `D:\DeepSeek`，可被
`KB_SCAN_ROOTS` env 或注册表 `scan_roots` 覆盖），**一次性**列出所有含
`docs` 的未登记项目及建议别名（取目录名），让用户一次勾选要登记哪些，
确认后按常规登记流程批量写入，最后统一验证回报。不要逐项目反复询问。

## 排除 `--exclude <目录名>`

把目录名写入注册表 `exclude` 数组——约定扫描将不再报告它（不影响已登记
项目）。只增删该条目，不动其它配置。

约束：不修改 `mcp/kb/server.py`；不写任何项目 docs；注册表只允许
`libraries` / `exclude` / `scan_roots` 三个键；同一问题连续两次写入失败
时停止并报告注册表文件内容，不反复重写。
