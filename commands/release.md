---
description: 基于当前已批准的主版本生成并发布正式 Release
argument-hint: [VERSION=<version>]
---

用户已通过调用本命令，显式授权为当前项目的已批准主版本创建正式 Release。

用户提供的可选版本参数：$ARGUMENTS

先读取当前项目中与本次操作相关的 `AGENTS.md`、session handoff、版本工作流、打包流程和 Release 约定；使用 `mod-version-workflow` 与 `mod-package` Skills 执行当前项目定义的正式发布流程。只读取本次发布需要的资料。

必须先确认：

1. Release 来源是已经批准并位于项目规定主分支或正式源状态的版本。
2. 提供的版本参数与项目版本规则、tag 和包名一致；未提供时可按项目规则确定，但不得猜测有歧义的版本。
3. 不存在会进入本次发布的未验收 test/fix 或无关工作区改动。
4. 正式包是完整安装包或项目明确规定的 release 形态，目录结构和依赖齐全。
5. ZIP 创建后已重新打开校验，清单、文件数量、关键路径和 SHA256 检查通过。
6. 必要的版本历史、发布说明和 session handoff 已更新。

本命令授权：

- 生成项目规定的正式 release 文件和完整交付包；
- 创建正式版本提交与 tag（项目规则要求时）；
- 推送与本次正式版本直接相关的提交与 tag；
- 创建 GitHub Release 并上传正式包（当前项目流程明确要求且相应访问能力可用时）。

本命令不授权：

- 将未验收的研究修改带入发布；
- 强制推送或覆盖既有 tag/Release；
- 跳过打包门禁；
- 发布与当前项目或版本无关的文件。

任何门禁失败时停止发布，不以“先发布后修复”代替验证。完成后报告来源版本、tag、包名、文件数量、SHA256、发布位置和校验结果。
