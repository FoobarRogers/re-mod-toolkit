---
description: 诊断 kb 知识库：连接、注册表来源、登记覆盖、分位统计与检索闭环抽验
argument-hint: [项目名]
---

用户调用本命令，要求诊断 kb 知识库（MCP server `re-mod-kb`）的健康状态。
本命令只读，不修改任何文件；发现的问题只报告与建议，不现场修复。

诊断对象（可选限定项目）：$ARGUMENTS

执行流程（按序执行，单项失败记录后继续）：

1. **server 连接**：调 `kb_list(project="all", depth=0)`。工具不存在或
   超时 → 检查插件 manifest 的 `mcpServers` 声明与 ZCode 设置页 MCP 状态，
   报告"server 未连接"与可能原因后停止。
2. **注册表与来源诊断**：kb_list 输出已含每个库的 `（来源: registry/env）`
   标注、`!!` 告警行（路径无效/覆盖/重复登记）与"未登记发现"清单——逐项
   汇总：登记库几个、env 与 registry 各几个、有无被覆盖或失效条目、发现
   多少未登记项目（建议用 `/kb-register --scan` 批量处理）。注册表文件
   路径以 server 的 `KB_REGISTRY` env 为准（未设则 `~/.zcode/kb/registry.json`），
   与 command 侧认知不一致时明确报告。
3. **分位统计**：对每个库统计 root（docs 根）与 evidence 的 md 数。
   **两者都为空**才提示"该库尚无现行认知层内容"；仅 evidence 空而 root 有
   现行文档属正常形态（正向结论住在 docs 根），不要误报。
4. **检索闭环抽验**（每库一条）：从该库实际文件里选已知存在的词——优先
   取 kb_list 标题树里的节标题词；**无标题文档从正文选独特词**；库在
   current 范围内为空时跳过抽验（不算失败）。先 `kb_search` 确认命中该
   文件，再 `kb_read` 确认能取回该节/该段原文——两步都通过才算检索闭环
   正常。不要用凭空想的主题词判断失效。
5. **状态行观察**：只在抽验结果里报告实际见到的 `[状态：…]` 行（含继承
   标注）。kb_search 返回有条数上限，**不得据此声称全库状态行总数**；
   抽验未见状态行时中性说明"抽验中未遇到状态行"，不做全库断言。
6. **回报**：紧凑列出——连接状态、库清单（别名/来源/current 文件数）、
   告警与冲突、未登记发现、抽验结果、建议动作清单。

约束：不修复、不改代码、不重写注册表；涉及 server 行为问题时引导用户
检查 `mcp/kb/server.py` 或重新加载插件，把现象原样报告。
