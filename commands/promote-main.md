---
description: 将当前已验收的 test/fix 版本正式提升并推送到 main
argument-hint: [VERSION=<version>]
---

用户已通过调用本命令，显式授权将当前已经验收通过的 test/fix 候选版本提升到 main。

用户提供的可选版本参数：$ARGUMENTS

先读取当前项目中与本次操作相关的 `AGENTS.md`、session handoff、版本工作流和版本记录；使用 `mod-version-workflow` Skill 执行项目自己的 main promotion 流程。只读取本次操作需要的资料。

必须先确认：

1. 当前候选版本、基线和目标主版本明确；如果提供了版本参数，它与实际候选一致。
2. 该 test/fix 已得到用户实机验收，或项目规定的等价验收证据已明确存在。
3. 本次提交只包含该候选相关修改；无关工作区改动得到保留，不被误提交。
4. 项目规定的验证、版本号更新和记录要求已经满足。
5. 当前分支和远端状态允许安全地完成 promotion，不需要强制推送或破坏历史。

本命令授权：

- 为当前已验收候选创建项目流程所需的提交；
- 按项目规则合并或提升到 main；
- 推送本次 main 更新；
- 更新与本次 promotion 直接相关的版本记录和 session handoff。

本命令不授权：

- 创建或发布正式 Release；
- 创建 GitHub Release；
- 提交与当前候选无关的改动；
- 强制推送、覆盖远端历史或绕过失败的验证。

如果无法确认候选身份、验收状态、变更范围或验证结果，停止 promotion，保留现状并准确说明阻塞项。完成后报告旧基线、新 main 版本、包含的提交、验证结果和仍未授权的 release 状态。
